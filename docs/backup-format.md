# KeyVault 备份格式 2

备份是 UTF‑8 JSON。配置名称和服务数据保存在加密的 `ciphertext` 字段里，建议文件名仍包含配置名称。导入方也支持旧版 `format: 1` 和裸 services JSON。

```json
{
  "format": 2,
  "kdf": {
    "alg": "Argon2id",
    "salt": "…",
    "params": { "memoryKiB": 32768, "iterations": 3, "parallelism": 1 }
  },
  "cipher": { "alg": "AES-256-GCM", "nonce": "…" },
  "ciphertext": "…",
  "checksum": "…"
}
```

- Argon2id 使用版本 1.3、口令的 UTF‑8 字节和每次导出生成的随机 16 字节盐，输出 32 字节 AES 密钥。AES‑GCM 使用独立生成的 12 字节 nonce 和 16 字节认证标签。`ciphertext` 编码密文及紧随其后的标签。所有二进制字段均为标准带填充 Base64。
- GCM 附加认证数据由 `format`、`kdf`、`cipher` 按示例顺序组成。对象内部字段也按示例顺序排列，以无多余空格的紧凑 JSON 编码成 UTF‑8。`checksum` 是该附加认证数据与 `ciphertext` 解码后字节拼接所得的 SHA‑256。
- 导入先检查文件大小、版本、算法、字段类型和校验和，再派生密钥并认证、解密和校验配置结构。文件上限为 6 MiB，明文上限为 4 MiB，Argon2 内存范围为 19–64 MiB，迭代次数为 2–4，并行度为 1–2。校验和用于识别非预期写坏。如果文件被修改且校验和被重新计算，GCM 仍会拒绝它，并显示口令或认证错误。

桌面先将完整密文写入目标同目录的临时文件，再原子替换目标。如果文件系统无法原子替换，导出报错。Android SAF 先完成加密，再通过 `ACTION_CREATE_DOCUMENT` 创建新文档并写入。在失败或取消时尝试删除不完整的文档。文档提供方可能拒绝删除，进程中断也可能留下不完整文件，导入校验会拒绝这些文件。

## 导入策略

- 新增是默认选项，确认后创建并切换到新的配置。可在预览修改新配置名称，重名时预览会显示加了序号的保存名称。
- 合并按服务名、配置项名精确匹配，再按 Key 值去重。相同 Key 值的不同备注可任选一份，也可在同一个 Key 下保留两份备注。同 ID 的 Key 值发生变化时可任选一份或保留两个值。不同的 API URL 可以选择保留本地或采用备份值。
- 覆盖保留目标配置的名称和 ID，使用备份替换其中的服务。预览显示变动条目数，第二次确认会列明删除、修改和新增数量。

预览分别计数服务、配置项和 Key，展开后可查看每条变更。提交前会检查目标配置是否仍与预览一致，所有数据在一次 DataStore 写入成功后生效。
